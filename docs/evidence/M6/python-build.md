# Compilazione Python 3.13.18

Il 2026-11-16 è stata avviata la build x64 Release con le dipendenze approvate e verificate in `python-source-dependencies.md`, senza Tcl/Tk. Visual Studio Build Tools 2022 / MSBuild è stato individuato; i sorgenti e le dipendenze erano nella cache del worktree. La compilazione è terminata con codice 1: 162 errori C1902, «Gestore database di programma incompatibile. Verificare l’installazione», nel progetto `_freeze_module`; nessun binario Python utilizzabile è stato verificato. Il log completo è nella cache locale `installer/.cache/python-build.log` (non versionato). La causa tecnica precisa non è stata accertata. Non sono state effettuate modifiche a Visual Studio o Windows né tentativi di compilazione alternativi.

Dopo autorizzazione esplicita del proprietario alla diagnosi e ai tentativi reversibili: un programma C minimo con `/Zi` ha compilato correttamente. La stessa build Python eseguita con accesso agli strumenti locali è riuscita (codice 0, 1 avviso C4267, 0 errori). Non si può attribuire con certezza la causa dell’errore iniziale. Il Python compilato riporta 3.13.18 x64; import di ssl, sqlite3, ctypes, bz2, lzma, zlib, decimal e pyexpat riusciti; OpenSSL 3.5.9, SQLite 3.50.4, Expat 2.9.0. Log di build in `installer/.cache/python-build-retry.log`. Le prove della libreria standard e il pacchetto embeddable restano separati.

Sei gruppi di test della libreria standard sono riusciti: 2.120 test eseguiti, 45 saltati (`test_zlib`, `test_bz2`, `test_lzma`, `test_sqlite3`, `test_decimal`, `test_ctypes`); log in `installer/.cache/python-stdlib-tests.log`. Il layout embeddable generato dagli strumenti CPython ha SHA-256 `a2aa39db83d68ec06f4f98908a55682685fa4696696549188b2dd333bfd03041`. È una build locale, non un binario ufficiale firmato da python.org.
